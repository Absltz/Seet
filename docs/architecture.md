# 架构与数据流

## 运行结构

浏览器运行 React 页面，Express 同时提供构建后的静态页面与 `/api` 接口。生产运行只需一个 Node.js 进程，无需单独安装数据库。Vite 用于构建和本地前端开发。

```text
文件 / 自然语言 / 麦克风
          ↓
React 工作台 → 本站 Express API → 千问
          ↓            ↓
共享数据计算       认证与记录隔离
          ↓            ↓
Recharts / 明细表   本地 .data 文件
          ↓
全局证据 + 问题专题证据 → AI 解读 → PDFKit → PDF.js 预览 / 下载
```

## 导入与计算

结构化文件先在浏览器读取为完整原始表格并保存。`server/importAgent.mjs` 将整表交给 AI 理解字段含义、识别标识与数值指标，再调用工具配置首张图表；超出完整提交容量时会明确报错，不截取样本冒充全部数据。自然语言和文本通过后端调用 AI 结构化，原始单元格与文件版本分别保留。

`src/analysis.mjs` 是前后端共用的确定性计算层。不同字段的筛选条件同时满足，同一字段的 `in` 数组匹配其中任意值。`filterSource` 返回筛选后的原始行，`buildView` 再执行分类或日期分组与汇总，不改写输入数据。

## Agent

`server/agent.mjs` 使用 Vercel AI SDK 和 千问 Function Calling。工具包括读取概况、配置视图、统计、质量检查、创建数据和提交最终答复。工具参数经过 Zod 及数据层校验后执行，成功结果才用于更新工作台。

导入完成后的日常提问使用字段概况及只读查询工具获取证据。`list_values` 扫描整个指定范围后去重分页，并返回准确总数与覆盖状态，避免把少量样本当作完整分类；条件查询可以定位缺失、负值和具体对象。操作通过 NDJSON 事件流展示，前端可中止请求。没有任意脚本执行工具。

## 报告

`server/report/snapshot.mjs` 构造整体与问题专题的独立快照。整体使用全部原始数据。问题专题读取该数据下全部已保存的用户输入，由 AI 归纳关注点并规划查询；程序从原始数据分别核算各个范围，再由 AI 综合解读，不机械沿用最新筛选或只回答最后一问。`explore.mjs` 计算候选图表及可核对的统计事实。

`narrative.mjs` 分为思考提纲和正文撰写。图表编号在撰写阶段连续化，再映射回实际证据；数字、身份标签、结构和图表引用均需核验，不通过时传递具体问题进行一次修订。

`compose.mjs` 合并两个部分，`pdf.mjs` 排版为中文 PDF；问题专题占一至两页。PDF 字节与解读随分析记录保存，`storage.mjs` 校验保存格式。预览使用已生成的字节，不重新调用模型。

## 认证与持久化

`auth.mjs` 使用随机盐和 scrypt 密码哈希。会话标识存入 HttpOnly Cookie，服务端会话驻留内存，重启后需重新登录。

`records.mjs` 按已认证账号决定读写文件，账号名经哈希生成记录文件名。分析自动保存，支持软删除和恢复。浏览器只记录当前账号上次打开的分析 ID，不存密码或完整分析。

运行数据写到 `.data/`，包括账号、分析、原始表格、文件版本、看板及回收站，不纳入仓库。密钥由后端从项目根目录 `.env` 读取；当前源码只提供空白配置模板，使用说明见根目录 README。

## 测试与依赖

`tests/` 使用 Node.js 测试运行器和模拟 HTTP 供应商，验证数据解析、单位、筛选、工具执行、认证、账号隔离、语音协议、报告范围与保存恢复。依赖版本由 `package-lock.json` 锁定。PDF 中文字体附带于 `assets/fonts/`。
